# Pinnwand

Shared Kanban task boards, mobile-first PWA. Create a board (Pinnwand), share it with a join code, and track Aufgaben across four fixed columns — Offen, Zu Erledigen, In Bearbeitung, Erledigt — with priorities and multiple assignees (Verantwortliche), synced in real time.

> Scaffolded from the Mahlzeit template (same stack, same feature-slice architecture and rules). Some `.claude/rules/*.md` still carry Mahlzeit domain examples (meals/households/dishes); the principles transfer directly — read them as conventions, and swap the nouns for boards/tasks. The offline-first *durable-mutation* persistence described in `pwa.md`/`tanstack-query.md` is Mahlzeit's; Pinnwand starts with a plain `QueryClient` and can adopt it later.

## Stack

- **Frontend**: React 19 + TypeScript + Vite + Tailwind CSS 4
- **UI primitives**: shadcn/ui (Base UI under the hood) in `src/shared/components/ui/`, added via `pnpm dlx shadcn@latest add <name>`
- **Theme**: "Modern Minimal" from [tweakcn](https://tweakcn.com/editor/theme?theme=modern-minimal) — tokens live in `src/app/index.css` (`:root` / `.dark`), bound to Tailwind utilities in the `@theme inline` block. Font: Inter.
- **State / Data**: TanStack Query (cache + realtime invalidation), TanStack Router (file-based routes in `src/app/routes/`)
- **Drag and drop**: dnd-kit (move cards between columns, reorder within a column)
- **Backend**: Supabase (Postgres + Auth + Realtime), run locally via the Supabase CLI
- **Validation**: zod at every API boundary (env parsed in `src/app/env.ts`)
- **Lint / format**: Ultracite (Biome preset) — auto-fix runs as a `PostToolUse` hook on every Write/Edit
- **Tests**: Vitest (unit); Playwright (e2e) can be added like Mahlzeit
- **Deployment**: static frontend + Supabase (Coolify or Cloudflare Pages)

## Essential commands

```bash
pnpm install                      # Install deps (Node 22, pnpm 10.18)
pnpm db:start                     # Boot local Supabase (CLI). Prints API URL + anon key → paste into .env
pnpm dev                          # Vite dev server on :5173 (regenerates routeTree.gen.ts)
pnpm build                        # tsc -b && vite build
pnpm preview                      # Preview the PWA build
pnpm check                        # Ultracite/Biome lint check
pnpm fix                          # Ultracite/Biome auto-fix (also runs automatically after edits)
pnpm test                         # Vitest unit tests

pnpm db:migration:new <name>      # New migration under supabase/migrations/
pnpm db:reset                     # Drop + re-apply every migration against the local db
pnpm db:types                     # Regenerate src/shared/types/database.ts from the local db (never hand-edit)
pnpm db:stop                      # Stop the local Supabase stack
```

First run: `pnpm install`, then `cp .env.example .env`, `pnpm db:start`, paste the anon key into `.env`, then `pnpm dev`.

## Domain model

- **board** (Pinnwand): `id, name, join_code (unique), created_by, created_at`. Created via the `create_board` RPC (also mints the owner membership + join code).
- **board_members**: `(board_id, user_id) PK, role (owner|member)`. The sharing/RLS boundary.
- **task** (Aufgabe): `id, board_id, column, title, description, priority, due_date (nullable), position, created_by, created_at, updated_at`.
  - `column` enum (fixed): `offen | zu_erledigen | in_bearbeitung | erledigt` → **Offen / Zu Erledigen / In Bearbeitung / Erledigt** (`src/features/tasks/columns.ts`).
  - `priority` enum: `niedrig | mittel | hoch`.
  - `position`: fractional index for drag-reorder within a column (write the midpoint between neighbours).
- **task_assignees**: `(task_id, user_id) PK` — many-to-many **Verantwortliche**, assigned from board members.

## Key invariants

- **RLS is on every table.** Sharing is via `board_members`; membership checks use the SECURITY DEFINER helpers `is_board_member` / `is_board_owner` (avoids policy recursion). Never expose other users' boards or tasks.
- **The service role key never reaches the client.** Only the anon key (`VITE_SUPABASE_ANON_KEY`).
- **Joining is by share code** through the `join_board_by_code` RPC — the client never inserts into `board_members` directly.
- **Optimistic updates on every mutation.** Drag-to-move must feel instant.
- **Realtime invalidates queries — never manually merge** `postgres_changes` payloads into TanStack Query cache.
- **UI never imports `api/` directly** — always via a hook.
- **Strict TypeScript.** No `any`, no `as unknown as X`. `verbatimModuleSyntax` + `exactOptionalPropertyTypes` are on — use `import type`.
- **The four columns are fixed.** No column CRUD; they are a Postgres enum + `TASK_COLUMNS`.
- **Surgical changes.** Every changed line traces to the request. Don't refactor adjacent code; match existing style. Notice unrelated dead code, mention it, don't delete it.

## Project constraints

- Mobile-first. On phones the four columns scroll horizontally with scroll-snap; a card open sheet uses `vaul`. Desktop shows the columns side by side.
- Sharing model: a `board` row + `board_members` rows (`role` = `owner` | `member`). A user creates any number of boards and sees every board they own or belong to as a list, then opens one. Boards are shared by **join code** (short, typable) minted with the board; a signed-in user joins by typing the code (`join_board_by_code`). Owners can rotate the code (`regenerate_join_code`) and rename/delete the board. Read the RPCs in `supabase/migrations/`, don't trust this summary.
- Sign-in: passwordless — magic link + 6-digit OTP fallback (`input-otp`), mirroring Mahlzeit. **Self-serve signup is disabled** (`enable_signup = false` in `supabase/config.toml`; `GOTRUE_DISABLE_SIGNUP=true` in prod): operators add users via Supabase Studio / the admin API, then users sign in passwordlessly. There is no public sign-up screen. Identity's source of truth is `public.profiles` (seeded by an `on_auth_user_created` trigger that fires when an admin creates the user), never `auth.users.raw_user_meta_data`.
- A task belongs to exactly one board and one column; assignees must be members of that board. Deleting a board cascades its tasks and assignees.
- Theme: owned by the `next-themes` provider in `__root.tsx` (persisted per device, applied before first paint via the no-FOUC bootstrap in `index.html`). The `appearance` feature provides the switch (System / Hell / Dunkel).
- All app logic lives in hooks and SQL (RLS + functions). No backend service beyond Supabase.

- `production-grade.md` — no half-baked code, no swallowed errors
- `security.md` — RLS, anon-key only, input validation
- `migrations.md` — append-only, RLS-first
- `architecture.md` — feature slice layer boundaries
- `documentation.md` — keep CLAUDE.md and rules in sync
