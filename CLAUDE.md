# Pinnwand

Shared Kanban task boards in a mobile-first PWA. Create a board (Pinnwand), share it with a join code, and track Aufgaben across four fixed columns (Offen, Zu Erledigen, In Bearbeitung, Erledigt) with priorities and multiple assignees (Verantwortliche), synced in real time.

> Scaffolded from the Mahlzeit template: same stack, same feature-slice architecture, same rules. Some `.claude/rules/*.md` still carry Mahlzeit domain examples (meals/households/dishes). The principles transfer directly, so read them as conventions and swap the nouns for boards/tasks.

## Stack

- **Frontend**: React 19 + TypeScript + Vite + Tailwind CSS 4
- **UI primitives**: shadcn/ui (Base UI under the hood) in `src/shared/components/ui/`, added via `pnpm dlx shadcn@latest add <name>`
- **Theme**: "Modern Minimal" from [tweakcn](https://tweakcn.com/editor/theme?theme=modern-minimal). Tokens live in `src/app/index.css` (`:root` / `.dark`), bound to Tailwind utilities in the `@theme inline` block. Font: Inter.
- **State / Data**: TanStack Query (cache + realtime invalidation), TanStack Router (file-based routes in `src/app/routes/`)
- **Offline-first**: the Query cache and paused task mutations persist to IndexedDB (`@tanstack/react-query-persist-client` over an `idb-keyval` async persister), so the installed PWA renders boards on a cold offline launch and resumes offline task writes on reconnect. Wiring lives in `src/shared/lib/idb-persister.ts` and `query-client.ts` (dehydrate allowlist), plus `PersistQueryClientProvider` in `main.tsx`. See `.claude/rules/pwa.md`.
- **Drag and drop**: dnd-kit (move cards between columns, reorder within a column)
- **Backend**: Supabase (Postgres + Auth + Realtime), run locally via the Supabase CLI
- **Validation**: zod at every API boundary (env parsed in `src/app/env.ts`)
- **Lint / format**: Ultracite (Biome preset). Auto-fix runs as a `PostToolUse` hook on every Write/Edit.
- **Tests**: Vitest (unit); Playwright (e2e) can be added like Mahlzeit
- **Deployment**: static frontend + Supabase (Coolify or Cloudflare Pages)

## Essential commands

```bash
pnpm install                      # Install deps (Node 22, pnpm 10.18)
pnpm db:start                     # Boot local Supabase (CLI). Prints API URL + anon key to paste into .env
pnpm dev                          # Vite dev server on :5173 (regenerates routeTree.gen.ts)
pnpm build                        # tsc -b && vite build
pnpm preview                      # Preview the PWA build
pnpm check                        # Ultracite/Biome lint check
pnpm fix                          # Ultracite/Biome auto-fix (also runs automatically after edits)
pnpm test                         # Vitest unit tests

pnpm db:migration:new <name>      # New migration under supabase/migrations/
pnpm db:reset                     # Drop + re-apply every migration against the local db
pnpm db:types                     # Regenerate src/shared/types/database.ts from the local db (never hand-edit)
pnpm db:stop                      # Stop the local Supabase stack
```

First run: `pnpm install`, then `cp .env.example .env`, `pnpm db:start`, paste the anon key into `.env`, then `pnpm dev`.

## Domain model

- **board** (Pinnwand): `id, name, join_code (unique), created_by, created_at`. Created via the `create_board` RPC, which also mints the owner membership and join code.
- **board_members**: `(board_id, user_id) PK, role (owner|member)`. The sharing and RLS boundary.
- **task** (Aufgabe): `id, board_id, column, title, description, priority, due_date (nullable), position, created_by, created_at, updated_at`.
  - `column` enum (fixed): `offen | zu_erledigen | in_bearbeitung | erledigt`, shown as **Offen / Zu Erledigen / In Bearbeitung / Erledigt** (`src/features/tasks/columns.ts`).
  - `priority` enum: `niedrig | mittel | hoch`.
  - `position`: fractional index for drag-reorder within a column (write the midpoint between neighbours).
- **task_assignees**: `(task_id, user_id) PK`. Many-to-many **Verantwortliche**, assigned from board members.

## Key invariants

- **RLS is on every table.** Sharing goes through `board_members`; membership checks use the SECURITY DEFINER helpers `is_board_member` / `is_board_owner` to avoid policy recursion. Never expose other users' boards or tasks.
- **The service role key never reaches the client.** Only the anon key (`VITE_SUPABASE_ANON_KEY`).
- **Joining is by share code** through the `join_board_by_code` RPC. The client never inserts into `board_members` directly.
- **Optimistic updates on every mutation.** Drag-to-move must feel instant.
- **Offline-first for the board surface.** Reads hydrate from IndexedDB on a cold offline launch; task writes pause offline and resume on reconnect. The allowlist in `query-client.ts` persists only board/task/member/profile reads and `tasks` mutations, never the auth session or join/sharing calls. Register a feature's resumable mutation defaults in `main.tsx` before the persister resumes.
- **Realtime invalidates queries.** Never manually merge `postgres_changes` payloads into the TanStack Query cache.
- **UI never imports `api/` directly.** Always go through a hook.
- **Strict TypeScript.** No `any`, no `as unknown as X`. `verbatimModuleSyntax` and `exactOptionalPropertyTypes` are on, so use `import type`.
- **The four columns are fixed.** No column CRUD; they are a Postgres enum plus `TASK_COLUMNS`.
- **Surgical changes.** Every changed line traces to the request. Don't refactor adjacent code; match existing style. Notice unrelated dead code, mention it, leave it.

## Project constraints

- Mobile-first. On phones the four columns scroll horizontally with scroll-snap, and a card opens a `vaul` sheet. Desktop shows the columns side by side.
- Sharing model: a `board` row plus `board_members` rows (`role` = `owner` | `member`). A user creates any number of boards and sees every board they own or belong to as a list, then opens one. Boards are shared by **join code** (short, typable) minted with the board; a signed-in user joins by typing the code (`join_board_by_code`). Owners can rotate the code (`regenerate_join_code`) and rename or delete the board. Read the RPCs in `supabase/migrations/` rather than trusting this summary.
- Sign-in is passwordless: magic link plus a 6-digit OTP fallback (`input-otp`), mirroring Mahlzeit. **Self-serve signup is disabled** (`enable_signup = false` in `supabase/config.toml`; `GOTRUE_DISABLE_SIGNUP=true` in prod). An operator adds users via Supabase Studio or the admin API, then those users sign in passwordlessly. There is no public sign-up screen. The source of truth for identity is `public.profiles`, seeded by an `on_auth_user_created` trigger that fires when an admin creates the user, never `auth.users.raw_user_meta_data`.
- A task belongs to exactly one board and one column; assignees must be members of that board. Deleting a board cascades its tasks and assignees.
- Theme is owned by the `next-themes` provider in `__root.tsx` (persisted per device, applied before first paint via the no-FOUC bootstrap in `index.html`). The `appearance` feature provides the switch (System / Hell / Dunkel).
- All app logic lives in hooks and SQL (RLS + functions). No backend service beyond Supabase.
